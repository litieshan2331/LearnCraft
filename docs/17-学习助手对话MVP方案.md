# 学习助手对话 MVP 方案

> 文档状态：待评审方案，尚未进入代码实现
>
> 更新日期：2026-10-09
>
> 适用范围：面向程序员的错题学习对话助手

## 一、MVP目标

学习助手的第一版不做教材库、题库 RAG、图片题目和开放式长期记忆管理。用户只需要把错题或代码问题带入对话，助手通过业务工具读取错题参数、学习者画像和掌握度，再通过两个子 Agent 完成诊断与启发式辅导。

MVP 只保证两个核心功能：

1. **错题归因分析**：定位用户在知识理解、推理步骤、API 使用、边界条件或粗心检查中的第一处实质错误，并给出可验证的修复方向。
2. **苏格拉底式启发**：围绕当前错误一次提出一个问题，引导用户解释自己的思路；根据回答逐步给提示，避免第一轮直接给出完整答案。

两个功能可以串成一个最小闭环：

```text
选择错题 → 获取题目与画像 → 分析错误 → 追问用户思路 → 给出分层提示
→ 用户重新作答 → 评估是否修复 → 写入学习记忆 → 推荐下一步
```

本方案是对现有四个批量生成工作流的交互式扩展。`assessment_generate`、`plan_generate`、`card_content_generate` 和 `posttest_generate` 可以继续作为后续学习计划能力复用，但不属于本 MVP 的必需链路。

## 二、产品边界

### 已包含

- 用户群体：正在学习编程的用户，首期不区分具体编程语言。
- 入口：学习起点页面中的学习助手对话，也支持从错题本进入指定错题对话。
- 数据来源：错题参数、用户画像、目标、历史掌握度和学习行为均通过内部 Function Calling 获取。
- 外部资料：继续使用现有 Tavily 工具，主要用于版本、API、库行为和近期技术资料核对。
- Skill：模型通过 `load_skill` 工具按当前问题动态加载教学规则。
- 记忆：系统自动沉淀结构化长期记忆，用户暂时不能查看、修改或删除。
- 输出：自然语言对话为主，关键诊断结果使用结构化对象保存。

### 暂不包含

- 教材库、题库和知识图谱 RAG。
- 图片上传、OCR、截图解析和白板交互。
- 用户自行编辑长期记忆。
- 多个主 Agent 之间的自由协商。
- 自动跨天排课、通知和复杂的间隔复习。
- 让模型直接读写数据库或任意本地文件。

## 三、Agent 分工

### 1. 学习教练主 Agent

主 Agent 是唯一面向用户的会话人格，负责理解意图、维护当前对话状态、选择 Skill、调用业务工具和安排下一步动作。它不直接猜测错题参数，也不把未验证的模型判断写入长期记忆。

主 Agent 的职责是：

- 判断当前请求属于错题分析、启发式追问、复盘还是普通编程问题；
- 获取必要的画像、错题和掌握度数据；
- 决定是否调用子 Agent；
- 控制每轮只提出一个主要问题；
- 将子 Agent 的结构化结果转成自然语言；
- 在用户完成修复后调用记忆写入工具；“完成修复”指用户能够针对原错误给出正确解释、修正代码或正确完成相似验证题，并且归因子 Agent 返回足够的验证证据；如果用户只是表示“明白了”，不能直接判定为完成修复；
- 在需要核对外部事实时调用 Tavily。

主 Agent 不负责自由规划长周期课程。MVP 的计划只表现为当前会话的下一步动作，例如“先回答这个追问”“再做一道相似题”。

### 2. 错题归因子 Agent

职责是根据工具返回的题目、用户答案、标准答案、代码运行结果和历史信息，输出结构化诊断，不直接和用户展开长对话。

输入至少包括：

- `wrong_question`：题目、选项或代码、用户答案、标准答案、解析；
- `learner_profile`：语言水平、目标、已知掌握状态；
- `mastery_state`：相关知识点当前掌握度和历史错误；
- `user_explanation`：用户在当前会话中对解题过程的描述。

输出至少包括：

```json
{
  "primary_error_type": "concept_gap",
  "knowledge_points": ["闭包", "词法作用域"],
  "first_substantive_error": "把函数定义时捕获的变量误认为调用时重新查找",
  "evidence": ["用户解释中把调用位置当成变量绑定位置"],
  "confidence": 0.86,
  "next_action": "ask_one_socratic_question"
}
```

允许的 `primary_error_type` 由代码白名单约束，例如 `concept_gap`、`reasoning_step`、`api_usage`、`boundary_case`、`careless_check` 和 `insufficient_evidence`。`insufficient_evidence` 表示需要主 Agent 继续追问，不能强行归因。

### 3. 苏格拉底导师子 Agent

职责是根据诊断结果和用户当前回答生成下一步启发，不直接重做整道题。它每次只返回一个主要问题，并可附带一个最小提示。

输出至少包括：

```json
{
  "question": "如果函数在定义时记录变量环境，那么调用发生在另一个位置时，应该查找哪一份变量？",
  "hint_level": 1,
  "hint": "先区分‘函数定义’和‘函数调用’两个时间点。",
  "expected_evidence": "用户能指出变量绑定发生在定义环境",
  "should_reveal_answer": false
}
```

连续两次回答仍不能推进时，主 Agent 可以要求导师提高 `hint_level`；只有达到设定阈值或用户明确要求答案时，才允许输出完整讲解。

## 四、对话和调用流程

### A. 从错题本进入

```text
前端携带 wrong_question_id
  ↓
主 Agent 调用 get_wrong_question
  ↓
主 Agent 调用 get_learner_profile 与 get_mastery_state
  ↓
调用错题归因子 Agent
  ↓
若证据不足：调用苏格拉底导师子 Agent 生成一个追问
若证据充分：先说明观察到的错误，再提出一个验证问题
  ↓
用户回答
  ↓
重复“分析当前回答 → 一个追问或一个提示”
  ↓
满足“完成修复”判定后调用 record_learning_memory
```

### B. 用户直接提问

```text
用户描述代码问题
  ↓
主 Agent 判断是否需要外部事实
  ↓
必要时调用 Tavily 核对版本/API 行为
  ↓
调用 load_skill 选择教学规则
  ↓
若存在已关联错题，调用错题归因子 Agent
否则直接调用苏格拉底导师子 Agent
```

### C. Skill 选择

对话模式不把所有 Skill 全文预先注入。系统提示词只包含允许的 Skill 摘要和使用约束，模型通过 `load_skill` 动态加载正文。

首期至少提供：

| Skill | 用途 |
| --- | --- |
| `misconception-repair` | 将错误拆成具体误区、证据和修复路径 |
| `socratic-tutor` | 一次一个问题，逐级增加提示 |
| `concept-bridging` | 将代码现象连接到抽象概念并说明边界 |
| `example-guidance` | 在确认理解后组织最小可运行示例 |

Skill 只能改变教学方式，不能覆盖系统规则、用户事实、工具权限和结构化输出约束。

## 五、Function Calling 工具

MVP 的工具由 Worker 统一提供，模型不能直接连接数据库。

| 工具 | 作用 | 是否写入 |
| --- | --- | --- |
| `get_wrong_question` | 获取题目、用户答案、标准答案、解析和代码运行信息 | 否 |
| `get_learner_profile` | 获取编程语言水平、学习目标和交互偏好 | 否 |
| `get_mastery_state` | 获取相关知识点掌握度、历史错误和最近练习 | 否 |
| `get_learning_context` | 获取当前会话已确认的事实和未解决问题 | 否 |
| `record_learning_memory` | 写入本次诊断、错误模式、干预结果和置信度 | 是 |
| `load_skill` | 在当前助手白名单内读取一个 Skill | 否 |
| `tavily_search` | 核对近期版本、API 或外部技术事实 | 否 |
| `mark_learning_step` | 记录本轮完成的分析、追问或修复动作 | 是 |

这里的“是否写入”表示该工具是否会修改服务端持久化数据：

- **否**：只读取或计算数据，不修改数据库。例如 `get_wrong_question`、`get_mastery_state`、`load_skill` 和 `tavily_search`。
- **是**：会新增或更新数据库记录。例如 `mark_learning_step` 写入本轮学习步骤，`record_learning_memory` 写入经过验证的学习经历记忆。所有写入工具都必须做权限校验、结构化校验和幂等处理。

工具安全边界：

- 所有 ID 由服务端校验，模型不能传任意路径、SQL 或用户 ID；
- `get_*` 工具只返回当前用户和当前会话范围内的数据；
- `record_learning_memory` 只接受 Zod 校验后的结构化字段；
- `tavily_search` 不能替代错题本和学习行为数据；
- Skill 加载次数和 Tavily 调用次数分别计数；
- 工具失败要以结构化错误回传模型，不能伪造成功数据。

## 六、记忆设计

MVP 采用四层记忆，但长期记忆不向用户开放编辑界面：

1. **短期记忆**：当前会话最近 20 轮消息组成的滑动窗口。每轮包含用户消息、助手消息和必要的工具结果摘要；超过 20 轮的消息仍然落库，但不再默认发送给模型。
2. **会话记忆**：本次会话的目标、已问问题、已给提示、未解决假设和当前阶段，单独保存并在每轮加载。
3. **学习经历记忆**：错因分类、具体误区、修复是否成功、使用过的提示级别和后续表现，写入独立的学习经历记录表。
4. **用户画像记忆**：编程语言、水平估计、常见错误模式、解释偏好和动机状态，继续保存在用户画像等独立业务表中。

每条对话消息都必须持久化。用户发送消息时先写入用户消息，助手完成回复后再写入助手消息；工具调用和工具结果至少保存可审计的名称、参数摘要、结果摘要、调用序号和时间戳。页面刷新时通过 `conversation_id` 重新读取会话状态和消息，按时间顺序恢复界面，再取最近 20 轮作为模型上下文。消息落库失败时不能向用户显示已成功发送的回复。

长期记忆只保存结构化事实、来源、置信度和更新时间。例如：

```json
{
  "memory_type": "error_pattern",
  "knowledge_point": "词法作用域",
  "pattern": "混淆定义时环境与调用时环境",
  "evidence_source": "wrong_question:8d...",
  "confidence": 0.86,
  "observed_at": "2026-10-09T10:00:00Z"
}
```

只有在错题归因有足够证据、或用户通过后续问题验证时，才写入学习经历记忆。模型的猜测必须标记为低置信度，不能直接升级为稳定画像。学习经历记忆是长期数据的一部分，但它与用户画像字段分开保存，后续可以用于更新画像或掌握度。

## 七、最小状态机

```text
new
  → context_loaded
  → diagnosing
  → waiting_for_user
  → hinting
  → checking_repair
  → mastered / needs_more_practice / unresolved
```

- `diagnosing`：错题归因子 Agent 分析当前证据；
- `waiting_for_user`：等待用户回答一个问题；
- `hinting`：苏格拉底导师生成当前层级提示；
- `checking_repair`：判断用户是否修复原错误；
- `mastered`：当前错误被验证修复，并写入学习经历记忆；
- `needs_more_practice`：理解已改善，但需要相似题验证；
- `unresolved`：证据不足、工具失败或多轮后仍未能判断。

## 八、MVP 界面

现有顶部导航可以保留，主入口仍然是“学习起点”；学习助手作为学习起点中的对话能力和从错题本进入的辅助页面：

- **学习起点**：主入口，设置语言、水平、目标和可用学习时间，并承载进入学习助手的入口；
- **学习助手**：对话区、当前错题卡片、当前阶段、下一步问题和提示按钮；
- **我的目标**：查看目标和当前会话产生的短期行动；
- **Agent 观测**：开发和管理员查看 Agent 状态、工具调用、耗时和错误码；
- **模型连接**：配置模型连接，不进入普通学习流程。

对话区不展示内部 Agent 名称、完整系统提示词、隐藏思考过程或长期记忆原文，只展示可理解的学习反馈。

## 九、验收标准

### 错题归因

- 能从工具取得错题和画像，不要求用户重复粘贴完整参数；
- 没有足够证据时先追问，不直接断言错误类型；
- 归因结果包含错误类型、知识点、证据、置信度和下一步动作；
- 归因结果通过结构化校验后才允许写入长期记忆。

### 苏格拉底启发

- 每轮最多一个主要问题；
- 默认不直接给出完整答案；
- 提示级别可以逐步增加；
- 用户修复后能进入验证或总结；
- 连续失败时能明确转入“需要更多练习”或“提供完整讲解”。

### 工具和运行时

- 所有工具调用带 `agent_run_id`、`conversation_id` 和调用序号；
- Skill、Tavily 和业务数据工具有独立调用上限；
- 模型无法访问任意文件、数据库或其他用户数据；
- 工具错误、模型错误和结构化校验错误可区分记录；
- 同一条学习记忆重复写入具有幂等性。

## 十、实施顺序

1. 增加学习助手会话和消息的最小领域模型；
2. 增加 `get_wrong_question`、`get_learner_profile`、`get_mastery_state` 三个只读工具；
3. 增加错题归因子 Agent 和结构化校验；
4. 增加苏格拉底导师子 Agent 和分层提示策略；
5. 将 `load_skill` 接入现有 ReAct 工具循环；
6. 增加 `record_learning_memory` 和 `mark_learning_step` 的幂等写入；
7. 接入 Tavily 的受控事实核对；
8. 最后接入前端学习助手页面和 Agent 观测信息。

在进入实现前，需要再次确认首期支持的编程语言、错题数据的现有接口、长期记忆的保留期限，以及 `record_learning_memory` 是否需要人工审核。这些决定会影响 API 合同、数据库 Schema、成本和隐私边界。

## 十一、数据库建模后的剩余实施步骤（简版）

1. 执行 `0010_learning_assistant_mvp` 迁移，并核对四张新表、索引和外键。
2. 实现会话、消息、对话运行和学习经历记忆的 Repository；所有消息落库，模型上下文默认取最近 20 轮。
3. 增加学习助手 API：创建/读取会话、发送消息、读取消息和查询运行状态。
4. 实现主 Agent 的工具编排，以及错题归因子 Agent、苏格拉底导师子 Agent 的结构化输入输出校验。
5. 接入 `get_wrong_question`、画像与掌握度查询、`load_skill`、`record_learning_memory`、`mark_learning_step` 和受控 Tavily 调用。
6. 增加对话运行的调用上限、权限校验、错误记录、幂等写入和学习经历记忆写入规则。
7. 在“学习起点”中接入学习助手对话页面，支持刷新后恢复会话和最近消息。
8. 用错题归因、连续追问、修复验证、工具失败和重复请求用例完成端到端验收。
