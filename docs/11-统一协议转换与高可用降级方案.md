# 统一协议转换与高可用降级方案（亮点一）

> 状态：待审查的概略方案；对应《10项目改造以及投递核心技术亮点》的亮点一。本文不改变现有实现。

## 结论

建议在现有模型调用与受控出网能力之上，增加**统一模型契约、厂商适配器和调用级故障切换**。调用方只提交消息、工具和所需能力，网关将厂商响应转换成统一事件；主模型遇到可恢复故障时，在有限预算内重试或切换到已授权的备用模型。首期先验证两种协议的转换与一条降级链路，不将“智能选模”或高并发数字写成已实现能力。

## 方案依据

目前 Agent Worker 已支持 OpenAI-compatible 请求、增量读取并聚合 SSE、受控出网审计及 429／5xx 的请求级重试；工作流从用户的默认连接获取模型。它尚无 Anthropic 原生协议适配、备用模型选择或对外 OpenAI 格式接口。现有 BullMQ 任务重试与模型调用重试属于不同层次，不能直接充当模型故障切换。

## 建议的调用链

```text
调用方 → 统一请求与能力校验 → 主／备候选选择
       → 厂商适配器 → 受控出网策略与审计 → 统一流式事件／完整响应
                         ↑ 超时、429、5xx 时有限重试与切换
```

1. **统一协议转换**：以 OpenAI Chat Completions 的常用消息、工具调用和流式事件为外部契约候选；内部定义厂商无关的请求、正文增量、工具参数增量、结束原因、用量和错误。保留现有 OpenAI-compatible 适配，新增 Anthropic 适配作为首个验证对象。适配器负责请求字段映射、厂商 SSE 事件归一化，出网层需在保留现有安全策略和审计的前提下扩展厂商请求路径与流解析；模型不支持的工具或结构化输出能力应明确拒绝，不静默丢字段。现有 Agent 可继续消费聚合后的完整响应，面向在线调用的 SSE 则逐事件转发，并传递取消与背压。
2. **高可用与降级**：只对超时、网络故障、429 和 5xx 等可恢复故障进行有上限的退避重试；考虑 `Retry-After` 与单次调用总时限。仍失败时，仅在**同一用户已授权、能力相容**的备用连接中切换。鉴权失败、参数错误、安全出网拒绝不切换；备用也失败则返回稳定错误码，避免无限重试。
3. **流式边界与观测**：在向下游发送首个响应事件前可以切换；发送后不得混接另一模型的内容，应结束该流并显式报错。记录每次尝试的厂商、模型、耗时、错误类别与实际用量，区分模型调用重试和 BullMQ 任务重试；不记录密钥、提示词或正文。用量缺失和失败尝试可能仍产生费用，不能把成功响应的 Token 数视为总账单。

## 审查时需要确定的边界

- 对外 OpenAI 格式接口是独立网关服务，还是先作为现有服务模块提供；这决定鉴权、部署和调用路径。
- 首批接入哪些厂商／模型，以及备用连接由谁配置、是否允许跨厂商、能力不兼容时如何处理；这决定模型接入与降级行为。
- 重试次数、总时限、费用上限和用量核算口径；这决定最坏延迟与成本。若需扩展模型连接或审计 Schema，应在实施前单独确认迁移方案。

以上参数与接入边界待审查确认后再进入代码实现；性能与可用性指标以故障注入、流式取消及并发压测结果为准。
