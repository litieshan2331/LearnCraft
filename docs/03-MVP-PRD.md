# LearnCraft 程序员学习 Agent — MVP 产品需求文档（候选稿）

## 0. 当前 P0 范围决策（2026-08-16，优先于后文旧版描述）

本节是当前实施的产品基线：P0 采用一次有效前测、任选计划节点、节点后测与本地代码 Demo；在线 Sandbox 与浏览器编辑器属于 P1。

### 0.1 学习目标、前测与学习计划

- 一个账户只有一份可编辑的当前学习画像。新学习目标和尚未生成的内容读取最新画像；前测、学习计划和已生成内容在创建时记录 `profile_version` 与必要输入快照，后续画像编辑不改写既有产物。
- 用户可创建多个自由主题学习目标，即使尚未开始前测。P0 提供目标列表、目标详情和开始前测、创建另一个目标、查看全部目标入口。
- 每个学习目标只允许一份有效前测。模型、网络错误或用户取消且尚未成功得到题集时可以重试；题集一旦成功生成，不提供重新生成前测入口。
- 用户提交前测后，服务端按首次生成时已保存的隐藏答案确定性评分，并只向本人展示正确答案与逐题解析；用户点击“生成学习计划”后，`plan_generate` 才以学习目标、前测题目、作答、分数、技能薄弱点和当前画像为输入生成学习计划。
- P0 只展示每个目标最新一份前测；历史数据保留在数据库，不做历史题集 UI。

### 0.2 计划节点闭环

```text
用户任选学习计划节点
  → 首次生成并保存唯一的知识内容与本地 Demo（不提供内容重生）
  → 用户标记该节点学习完成
  → 生成该节点的一份后测；答案与解析已随题目隐藏保存
  → 提交后由服务端确定性评分并仅向本人展示答案、解析与反馈
  → 可重新生成新的后测题集；历史题集、作答和错题解析均可查看
```

- 计划节点不强制线性解锁；节点状态用于记录学习情况，不阻止用户直接进入任意节点。
- P0 优先完整实现一个计划节点的上述闭环；计划本身可包含多个节点。
 后测为节点级测验，题量 5–10 题、推荐 5–8 题、仅单选题。每次重新生成后测都形成独立记录；P0 同时提供最新结果和历史题集列表，用户可查看本人历史作答、错题与解析。

### 0.3 本地代码 Demo 与 P1 在线沙箱

- P0 的可运行代码 Demo 是可复制到本地运行的产物，不是浏览器内执行服务。每个 Demo 必须提供运行语言与版本、文件与完整代码、中文注释、入口文件、依赖安装步骤、运行命令、预期输出、调用顺序和常见报错排查提示。
- P0 不创建 `CodeRun`、不运行模型或用户代码、不部署 `code-runner`，也不要求模型代码经服务器预运行验证。
- P1 再引入在线代码沙箱、浏览器编辑器、在线 stdout/stderr、运行日志、资源限额与安全隔离；届时必须重新确认支持语言、隔离方案和运行策略。

## 1. 产品概述

### 1.1 一句话定位

面向程序员的网页学习 Agent：用户只需描述想学什么、会什么和偏好，系统通过一次规划生成可执行的学习路线，并在每张卡片中提供解释、可靠资料、代码练习和测验反馈。

### 1.2 背景与机会

程序员学习通常要反复在课程、文档、视频和代码之间切换；连续向大模型提问也很难沉淀为可执行计划。LearnCraft 将这些问答编排为有状态的工作流，把“获取信息”变成“按目标实践并验证掌握”。

### 1.3 MVP 假设

1. 用户愿意先填写少量结构化信息并完成 10～20 题单选前测；系统提供“正常”和“困难”难度卡片，并在前测题序中逐步提高难度。
2. 对一个明确的技术主题，结构化路线比泛泛的聊天答案更容易开始学习。
3. “看一个短内容 → 在本地运行一个小 Demo → 做题并得到反馈”足以形成首次价值。
4. 基于前测和节点后测分数的简单规则，已经能提供有感知的个性化，而不必在 MVP 中训练推荐模型。

### 1.4 推荐试点边界

首版允许用户创建任意面向程序员的技术主题学习目标，桌面网页优先，简体中文界面。主题以自由文本保存，并由后续 Agent 根据主题、学习背景和目标生成前测与路线；P0 的 Demo 为本地运行说明，不能把“可创建目标”等同于“平台已支持该语言的在线运行”。

## 2. 目标、非目标与成功定义

### 2.1 MVP 目标

- 新用户在 5 分钟内完成目标输入和前测，并得到一条可开始执行的路线。
- 用户能打开任意一张学习卡，阅读内容、取得可复制到本地的 Demo、完成该节点的后测。
- 系统能根据前测生成路线，并根据节点后测给出复习或提高难度建议。
- 关键状态和尝试记录可持久化，刷新或重新登录后可以继续。
- 通过小规模试点验证“主动规划 + 动手实践”是否比单次问答更有用。

### 2.2 明确非目标（MVP 不做）

- 社区、关注/评论、社群、排行榜和分享。
- 学习进度条、成就/徽章、游戏化、完整学习报告或证书。
- 原生移动端、直播课、付费/订阅和企业管理后台。
- 在线编译、执行与调试环境；浏览器代码编辑器、运行日志与资源隔离统一放到 P1。
- 自动抓取任意网页、视频转写、用户上传资料的全量 RAG（首版只使用受控资料目录和链接）。
- 代码部署、持久化文件、外网访问、GPU 或长时任务；P0 不执行用户或模型代码。模型推理由服务端调用托管模型 API，不属于用户代码执行环境。
- 允许用户直接修改系统提示词；只提供安全的结构化学习偏好选项。
- 由 Agent 代替教师做高风险/职业资格判断；内容需注明“辅助学习”定位。

### 2.3 MVP 成功门槛（首轮试点）

- ≥80% 试点用户能在一次会话内生成路线。
- ≥60% 生成路线的用户能打开任意节点并完成一次节点后测。
- ≥40% 生成路线的用户完成一个节点的“内容 + 本地 Demo + 测验”闭环。
- 路线/卡片生成结构化成功率 ≥95%；失效请求有可理解的重试/降级提示。
- P0 不存在服务端代码执行入口，用户数据越权读取为 0。

## 3. 用户与使用场景

### 3.1 目标用户画像

**主用户：程序员学习者**

- 初级到中级，正在学习一个具体技术并希望做出可运行结果。
- 能阅读基础技术英文，但希望用中文理解重点。
- 时间碎片化（每次 15～60 分钟），不想反复搜索和整理资料。
- 需要根据已有基础、目标岗位/项目和内容偏好定制学习顺序。

**暂不服务：**需要系统课程运营、班级管理、教师批改或认证考试的机构用户。

### 3.2 核心 JTBD

> 当我想在有限时间内学会某个编程主题时，我希望只描述自己的目标和基础，就能得到一条适合我的学习路线；每一步都有可读材料、可运行练习和验证题，系统还能根据结果调整下一步，让我知道现在该做什么。

### 3.3 典型场景

1. **从零上手：**“我会一点 Python，想在两周内写一个天气 API”，系统先测基础，再安排概念、语法、实战、调试四阶段。
2. **查漏补缺：**“我能写 CRUD，但不会异步”，前测发现协程薄弱，路线优先安排异步概念和小练习。
3. **资料提炼：**用户选择“文档优先”，卡片先给短解释和官方文档链接，而不是堆砌大量搜索结果。

## 4. 产品原则与体验约束

- **先行动后扩展：**首屏引导用户明确目标并尽快生成第一张可执行卡。
- **一次输入、分步执行：**用户用一次结构化目标输入启动前测；用户查看评分解析后决定是否发起规划，并在任意节点主动发起内容或后测生成。产品采用两个职责隔离的工作流 Agent，而不是无限聊天窗口。
- **每张卡一个结果：**卡片必须有可观察的掌握标准，避免长篇百科。
- **可解释的个性化：**显示“为什么安排这一卡”（来自前测薄弱点/目标），不展示不可理解的模型分数。
- **结构化 Agent：**模型输出必须通过 schema 校验、引用校验和规则校验；失败时降级为模板或重试。
- **本地 Demo：**P0 明确告知用户将代码复制到本地运行，并提供环境、依赖、命令、预期输出和常见报错；不伪造服务器验证结果。
- **不制造虚假确定性：**外部资料显示来源和抓取时间；无法验证的链接不作为“官方资料”呈现。
- **轻量状态而非完整进度产品：**MVP 只保存目标、节点完成和测验状态以支持恢复与反馈，不展示全局进度条、成就或学习报告。

## 5. MVP 核心流程

```text
注册/登录
   ↓
维护一份当前学习画像；创建一个或多个自由主题学习目标
   ↓
为目标生成一次前测（用户选择 10～20 题的单选题；正常/困难；题序逐步提高难度）
   ↓
用户提交前测 → 服务端评分并展示正确答案/解析 → 保存分数、作答与薄弱点快照
   ↓
用户点击“生成学习计划” → 学习规划 Agent 生成路线（概念 → 语法 → 实战 → 调试；输入为目标、前测与当前画像）
   ↓
用户任选学习计划节点 → 节点教学 Agent 首次生成并保存唯一内容与本地 Demo
   ↓
用户标记节点完成 → 生成节点后测（用户选择 5～10 题，推荐 5～8 题；仅单选题）
   ↓
提交后测 → 规则评分、正确答案、逐题解析与薄弱点标签 → 可生成新题集，并查看历史后测错题
```

### 5.1 状态机（最小实现）

- 路线：`draft` → `active` → `completed`（MVP 可只实现 `active`）。
- 卡片：`not_started`、`in_progress`、`completed`、`needs_review`；前置关系只用于展示与建议，不能阻止用户进入任意节点。
- 测验尝试：`in_progress`、`submitted`、`grading`、`graded`、`grading_failed`。
- 本地 Demo：作为每个节点唯一成功的 `card_content` 结构化内容保存；P0 不提供内容重新生成或版本切换，不存在运行任务状态。
- 同一用户同一路线只允许一个当前活动版本；重新规划生成新版本并保留旧记录。

## 6. 功能需求

优先级：**P0** = 发布阻断项，**P1** = 首轮试点应有，**P2** = MVP 后评估。

### 6.1 账户与学习者档案

| ID | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-01 | P0 | 用户注册/登录/退出；只能访问自己的学习数据 | 未登录不能读取路线、尝试和代码记录；越权请求返回 403/404 |
| FR-02 | P0 | 创建或编辑唯一的当前学习者档案 | 每账户只有一份画像；填写整体编程经验、学习背景、每周时间和内容偏好，不填写与具体主题重复的起始水平；编辑后仅影响新目标和未生成内容 |
| FR-03 | P1 | 结构化内容偏好 | 至少支持“文档优先/视频优先/代码优先”、解释深度、语言；偏好作为 Agent 输入 |
| FR-04 | P1 | 再次进入可恢复最近活动路线 | 刷新、重新登录后保留当前卡和已提交结果；重复提交具备幂等性 |
| FR-03A | P0 | 用户模型连接与选择 | 用户可保存 OpenAI-compatible `base_url`、API Key、模型名；API Key 仅可写入/覆盖并加密保存；用户设置账户默认连接，P0 的两个 Agent 均使用该连接。System Prompt、输出 Schema、Token/超时、工具权限、重试和思考模式由开发者内部 Profile 配置控制，不向用户暴露 |

### 6.2 目标输入与前测

| ID | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-05 | P0 | 目标输入表单与目标列表 | 支持自由 `topic`、一句话描述、期望成果和时间等结构化字段；一个用户可创建多个目标，缺少目标时阻止提交并给出示例 |
| FR-06 | P0 | 生成并完成前测 | 用户可选择 10～20 题，默认推荐 12 题；仅生成单选题；提供“正常”“困难”难度卡片，前测按题序逐步提高难度；显示题目进度（非全局学习进度条） |
| FR-07 | P0 | 前测评分与薄弱点 | 单选题由服务端按首次生成时保存的隐藏答案确定性评分；交卷前题目 API 不返回答案/解析，交卷后仅向作答用户返回总分、能力标签、正确答案与逐题解析；结果持久化，不调用模型 |
| FR-08A | P0 | 用户确认生成学习计划 | 前测已评分后展示明确的“生成学习计划”入口；未点击不创建 `plan_generate` 或消耗模型额度；点击后才使用目标、画像和前测交接快照生成路线 |
| FR-08 | P0 | 前测唯一性与异常重新发起 | 每个目标只允许一份成功生成的前测；模型、网络错误或用户取消且尚未得到题集时，允许重新发起生成；题集成功后不提供重新生成入口。答题提交幂等，历史数据只保留不展示 |

### 6.3 个性化学习路线

| ID | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-09 | P0 | 基于档案和前测生成路线图数据 | 用户确认后由学习规划 Agent 生成 6～12 张卡，覆盖“概念→语法→实战→调试”；生成时保存目标、前测题目/作答/分数/薄弱点、`profile_version` 与必要输入快照；每卡有标题、自然语言简要描述、目标、阶段、前置、预计时长、完成标准、难度 |
| FR-10 | P0 | 路线可读展示与任意节点入口 | 用户能看到阶段和卡片关系，并可直接打开任意节点；前置关系不构成访问锁，不要求拖拽编辑 |
| FR-11 | P0 | 结构化输出校验和版本化 | Agent 输出不符合 schema 时自动重试/模板降级；保存 prompt/model/schema 版本和路线版本号 |
| FR-12 | P1 | 用户确认或重新生成 | 展示“安排理由”和预计投入；用户可在限制次数内重新生成（例如每日 2 次），不允许任意改写系统约束 |

所有真实模型调用均使用 Provider SSE 流式请求。Worker 必须等待流完成、聚合完整响应并通过响应大小限制后，才执行 JSON 提取和 schema 校验；对题集等结构化任务在请求载荷中设置 `response_format: {"type": "json_object"}`，并使用顶层 JSON 约束与一次受控修复。前端只接收 AgentRun 状态事件和已校验的最终产物，不能展示或持久化未完成的模型 JSON。

### 6.4 学习卡内容

| ID | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-13 | P0 | 按节点首次生成唯一内容 | 节点教学 Agent 以节点自然语言简要描述为主要输入，生成并保存唯一内容包：掌握目标、核心解释、示例、练习、提示、参考资料和内部教学记忆；`practice/debug` 节点另含本地 Demo、调用顺序和中文注释。仅在尚未成功保存内容时允许失败重试，不提供成功后的内容重生入口 |
| FR-14 | P0 | 资料链接与来源 | 支持文档和视频链接；显示来源名称、URL、类型和校验状态；无效链接不标记为推荐，必要时提供受控备用资料 |
| FR-15 | P0 | 实战/调试本地代码 Demo | AI 生成可复制到用户本地运行的完整 Demo，含语言与版本、文件清单、入口、依赖安装步骤、运行命令、预期输出、调用顺序、关键中文注释、结果解释和常见报错排查；页面明确说明 P0 不在服务端预运行或执行代码 |
| FR-16 | P1 | 内容质量恢复策略 | 仅在产品重新确认“是否允许内容重生、如何标记用户已学习内容”后才评估换一种解释或多版本；不得改变 P0 的每节点唯一成功内容规则 |
| FR-17 | P1 | 安全渲染 | Markdown/代码高亮经过 XSS 过滤；外部链接新窗口打开并带安全 rel 属性 |

### 6.5 本地代码 Demo 与 P1 在线沙箱

| ID | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-18 | P0 | Demo 可读与可复制 | 代码块、文件清单、依赖安装、运行命令、预期输出、调用顺序和排错提示均可复制；不展示运行按钮、编辑器或伪造的执行结果 |
| FR-19 | P1 | 浏览器代码编辑器与受限沙箱 | 在重新确认语言、依赖和隔离方案后，支持编辑、运行、重置；默认无网络、无持久磁盘、非特权用户，并配置 CPU/内存/时长配额 |
| FR-20 | P1 | 在线结果与错误反馈 | 展示 stdout、stderr、测试通过/失败、耗时，并将实际输出对应到调用顺序；错误不泄露服务端路径或密钥 |
| FR-21 | P1 | 运行记录 | 保存代码快照、结果、资源消耗、时间和卡片 ID；同一请求有幂等键，防止重复运行 |

### 6.6 节点后测、反馈与基础调节

| ID | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-22 | P0 | 节点后测出题与历史 | 用户标记任意节点完成后，可选择 5～10 题（推荐 5～8 题）生成该节点后测；节点教学 Agent 仅以该节点固定内容、Demo 和教学记忆出题。每次重新生成创建独立题集，不覆盖历史题集或作答 |
| FR-23 | P0 | 自动评分、解析与错题回顾 | 服务端按首次生成时保存的隐藏答案确定性评分；交卷后仅向作答用户返回得分、正确答案、逐题解析和薄弱点标签。节点页提供后测历史列表及任一历史题集的错题、作答和解析；评分不调用模型 |
| FR-24 | P0 | 节点完成与后测关系 | 节点完成是用户显式操作，不以分数或前置节点限制访问；后测结果不会改写已经生成的路线或阻止用户进入其他节点 |
| FR-25 | P0 | 基础规则调节 | 使用确定性后测分数给出建议：≥80% 提示掌握，50～79% 建议复习，<50% 提示薄弱点与重做后测；不插入补强节点，不改写当前路线 |
| FR-26 | P1 | 调节可解释、可回退 | 明示触发原因；每张原卡最多插入一张补强卡，避免循环；用户可跳过补强卡并记录原因 |
| FR-27 | P1 | 路线版本历史 | 动态调整产生新版本或事件记录，已完成卡和历史成绩不可被覆盖 |

### 6.7 最小可观测性与运营能力

| ID | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-28 | P0 | Agent 调用可追踪 | 为一次规划/内容/评分调用记录 trace ID、耗时、模型、token/费用估算、重试次数和错误类型；不记录明文密钥 |
| FR-29 | P0 | 用户可理解的失败态 | LLM、资料或异步任务失败时，页面显示状态、重试按钮和替代路径；不能静默卡死 |
| FR-30 | P1 | 速率与配额 | 对规划、内容生成、代码运行和测验提交设置用户级限流/每日配额，防止成本和滥用失控 |

## 7. 用户故事与验收场景

### US-01：创建学习目标

**作为**程序员学习者，**我希望**描述目标、当前水平和时间，**以便**系统生成适合我的学习计划。

- Given 用户已登录且目标字段为空，When 点击生成，Then 页面阻止提交并显示填写示例。
- Given 必填字段完整，When 提交，Then 创建一个唯一目标并进入目标详情；用户可选择开始前测、创建另一个目标或查看全部目标，不重复创建相同请求。

### US-02：完成前测

**作为**学习者，**我希望**先回答少量问题，**以便**路线能避开我已掌握的内容。

- Given 前测可用，When 用户提交全部单选题，Then 服务端同步完成确定性评分并显示分数、能力标签和每题解析。
- Given 模型、网络错误或用户取消且题集尚未成功生成，When 用户重新发起前测，Then 系统创建新的生成任务并明确展示状态；题集成功生成后不提供重生入口。未完成评分前不能生成路线或静默给分。

### US-03：获得并理解路线

**作为**学习者，**我希望**看到每张卡的目标和安排理由，**以便**知道下一步做什么。

- Given 前测已评分且用户点击“生成学习计划”，When 学习规划 Agent 成功生成路线，Then 展示 6～12 张卡、四个阶段、前置关系和节点简要描述；用户可直接打开任意节点。
- Given 生成结果非法，When 自动修复/重试仍失败，Then 不保存半成品，显示重试或模板路线入口。

### US-04：学习并获取资料

**作为**学习者，**我希望**按我的偏好获取短解释、文档/视频和练习，**以便**减少资料筛选时间。

- Given 用户选择“文档优先”，When 打开卡片，Then 首屏先显示解释和文档链接，且每个链接有来源/校验状态。
- Given 内容生成中，Then 用户看到可取消的加载态；刷新后可恢复或重试。

### US-05：获取本地代码 Demo

**作为**学习者，**我希望**获得能够复制到本地运行的代码和说明，**以便**从代码层面理解当前知识点。

- Given 用户打开实战/调试节点，Then 看到完整文件、代码、中文注释、语言版本、依赖安装、入口、运行命令、预期输出、调用顺序和排错提示。
- Given 用户复制代码，Then 页面明确提示在其本地环境运行；P0 不提供运行按钮、stdout/stderr 或服务器预运行结论。

### US-06：测验和反馈

**作为**学习者，**我希望**完成卡后立即知道哪里错，**以便**决定重试还是继续。

- Given 用户标记一个节点完成并提交 5～10 题单选后测，When 评分完成，Then 返回总分、逐题解析和薄弱标签，且记录题目与答案版本。
- Given 用户希望继续练习，Then 保留原题集、原作答和错题解析，并允许基于同一固定内容重新生成该节点后测；新题集形成独立记录且可从历史列表打开。

### US-07：路线动态调整（P1）

**作为**学习者，**我希望**系统根据结果调整下一步，**以便**学习节奏与实际水平匹配。

- Given 节点后测分数 ≥80%，Then 当前节点展示掌握建议。
- Given 节点后测为 100%，Then 为下一次内容生成提供提高难度建议，并说明其不会改写当前路线历史。
- Given 分数 <50%，Then 系统在 P1 才可建议或插入不超过一张补强卡，并说明触发原因。
- Given 用户选择跳过补强卡，Then 在 P1 记录跳过事件并允许继续，不删除历史结果。

### US-08：恢复学习

**作为**学习者，**我希望**稍后回来还能继续，**以便**不必重复前测和已生成内容。

- Given 用户关闭页面后重新登录，Then 恢复最近活动路线、当前卡和历史尝试。

## 8. Agent 工作流与边界

### 8.1 推荐工作流节点

1. **学习规划 Agent / InputNormalizer：**以 `learning_architect:{goal_id}` 为逻辑会话，校验目标和当前画像，形成前测输入快照。
2. **学习规划 Agent / AssessmentGenerator：**生成 10～20 道单选前测，并在同一次输出中提供隐藏答案、解析和能力标签；前测成功后不重复生成。
3. **服务端 AssessmentEvaluator：**仅按已保存隐藏答案确定性评分；交卷后仅向题主展示答案、逐题解析、分数和薄弱点，不调用模型。
4. **学习规划 Agent / PlanPlanner + PlanValidator：**仅在用户点击“生成学习计划”后读取目标、当前画像和前测交接快照，生成并校验四阶段路线、节点依赖和自然语言 `node_brief`。
5. **节点教学 Agent / CardContentGenerator：**以 `node_tutor:{plan_node_id}` 为逻辑会话，读取目标摘要、`node_brief` 和最新画像，首次生成唯一的内容、本地 Demo 与内部 `teaching_memory`；成功后没有内容重生入口。
6. **节点教学 Agent / PostTestGenerator：**用户标记节点完成后，只以固定内容、Demo 与 `teaching_memory` 生成 5～10 道单选后测；每次重练生成独立题集，并在同一次输出中保存隐藏答案和解析。
7. **LearningFeedbackPolicy：**服务端根据后测历史中的当前题集评分使用显式规则给出复习或提高难度建议；P0 不解锁/锁定节点、不插入补强节点，模型不能绕过规则。

### 8.2 输出契约（产品层要求）

- 所有 Agent 输出为版本化 JSON schema，再转换为 UI 文案。
- 必须携带 `trace_id`、`prompt_version`、`model`、`source_refs`（如有）和 `generated_at`。
- 缺失必填字段、循环依赖、未知主题、不可验证 URL 时不得直接展示为成功；进入修复、降级或人工可观测错误态。
- Agent 不得执行任意工具调用或访问用户私密数据；P0 不存在把模型输出送入代码沙箱的链路。
- `AssessmentItem` 在 P0 只能是 `single_choice`，必须包含至少两个选项和隐藏答案；用户答案是不可信输入，不能触发工具调用。
- `LocalDemoSpec` 必须包含语言与版本、完整文件与源码、入口、依赖、运行步骤、预期输出、调用顺序、中文注释和常见报错排查；首次成功保存后不可由用户重新生成。该次输出还必须有内部 `teaching_memory`，供同一节点的后测出题使用；不得带有 Runner 验证摘要或伪造执行结果。

## 10. 非功能需求与质量门槛

### 10.1 性能与可用性

- 普通页面/API p95 ≤1 秒（不含 Agent）；单选题评分同步完成，提交结果立即返回。
- 路线生成 p95 ≤60 秒，卡片内容与本地 Demo 生成 p95 ≤30 秒；长任务显示阶段性状态。
- Agent/资料暂时不可用时，用户能在 3 次以内重试或走模板降级；不出现无限 loading。
- 试点期间关键链路可用性目标 ≥99%（按可观测请求计算）。

### 10.2 安全与隐私

- P0 不运行用户或模型代码；P1 引入代码运行前，必须确认隔离容器/微 VM、非 root、无默认网络、资源配额与超时方案。
- 所有对象按 `user_id` 鉴权；服务端再次校验，不信任前端卡片 ID。
- Markdown、URL 与代码展示均进行内容过滤和 XSS 防护；错误信息不泄露路径、环境变量或内部提示词。
- API 与 Agent 设置速率限制、审计日志和成本上限；密钥仅从服务端密钥管理读取。
- 明确告知外部链接、模型生成内容和本地运行代码的风险；提供删除数据入口。

### 10.3 可访问性与兼容性

- 桌面优先的响应式网页，支持主流 Chromium/Firefox 最近两个大版本。
- 键盘可操作、颜色不作为唯一状态提示、代码/错误信息可复制。
- MVP 界面为简体中文；技术关键字保留英文并可复制。

## 11. 埋点与指标

### 11.1 核心漏斗事件

`signup_completed` → `goal_submitted` → `front_assessment_started` → `front_assessment_submitted` → `plan_generated` → `node_opened` → `content_ready` → `local_demo_viewed` → `node_completed` → `post_assessment_submitted` → `post_assessment_scored`。

每个事件至少带：匿名 user_id、goal_id、plan_version、card_id（如有）、时间、结果/错误码、trace_id。不要把密码、API key 或未脱敏代码放入分析系统。

### 11.2 指标定义

- **首次价值时间（TTFV）：**从 `goal_submitted` 到首次 `card_opened` 且内容可读，目标中位数 ≤5 分钟。
- **规划成功率：**`plan_generated / goal_submitted`，目标 ≥95%（含模板降级）。
- **首卡启动率：**`card_opened / plan_generated`，目标 ≥75%。
- **首节点闭环率：**取得本地 Demo、标记节点完成并提交后测的用户 / 生成路线用户，目标 ≥40%。
- **测验有效率：**可评估提交 / 测验提交，目标 ≥98%。
- **后测重练率：**重新生成节点后测的次数 / 已评分节点后测次数；用于观察练习需求，不设硬门槛。
- **成本/延迟：**每条路线、每张卡的 token、费用估算、p50/p95 延迟和失败率。
- **质量与安全：**失效资料链接率、用户纠错率、本地 Demo schema 缺失率、越权数、敏感信息告警数。

## 12. 版本范围与里程碑

### M0：基础骨架

账号、数据库 schema、对象鉴权、Agent trace、错误码和受控题库/资料目录。

### M1：前测到路线

目标表单、10～20 题单选前测、正常/困难难度、确定性评分、路线生成/校验/展示、版本化和模板降级。

### M2：卡片学习

卡片内容生成与缓存、文档/视频引用、实战/调试 Demo schema、调用顺序/注释结果、Markdown 安全渲染。

### M3：单节点学习闭环

任意节点内容与本地 Demo、用户标记完成、节点级 5～10 题单选后测、确定性评分与可重新生成后测练习。

### M4：P1 在线执行与基础调节

在单独确认语言、隔离与成本策略后，加入在线 Sandbox、浏览器编辑器与运行记录；随后评估补强卡、可解释事件、限流/成本控制和端到端监控。

## 13. 发布验收清单（Definition of Done）

- [ ] 新用户可完成“目标 → 一次前测 → 评分 → 路线 → 任意节点”主流程，且页面有加载、空态、错误、重试态。
- [ ] 路线至少 6 张卡并覆盖四阶段；前置关系无环；Agent 输出 schema 校验通过。
- [ ] 任一实战/调试节点含解释、至少一个可验证来源、本地 AI Demo、文件/入口/依赖/运行命令、预期输出、调用顺序、中文注释与排错提示；没有在线运行入口或预运行声明。
- [ ] 节点完成后可生成 5～10 题单选后测，评分后可重新生成后测练习；前测每目标只成功生成一次；答案不外泄，确定性评分和复习/提高难度建议均有审计记录。
- [ ] 刷新/重新登录可恢复；对象越权、XSS 和密钥泄漏测试通过。
- [ ] 关键事件、Agent trace、延迟/成本和失败率可查询；达到成功门槛后才扩大主题范围。

## 14. 风险与缓解

| 风险 | 影响 | 缓解/监控 |
|---|---|---|
| Agent 生成路线空泛、重复或超出水平 | 学习价值低 | 单主题试点、固定 schema、四阶段规则、前置无环校验、用户纠错埋点 |
| 资料链接失效或模型幻觉引用 | 误导用户 | 受控来源目录、URL 健康检查、显示来源/校验时间、失效自动降级 |
| 测验题目质量或答案泄露 | 错误学习建议或作弊 | 受控题库、隐藏答案、确定性评分、公开响应脱敏、题目版本留存并允许重试 |
| 本地 Demo 难以在用户机器运行 | 首次价值下降 | 输出明确语言版本、依赖、命令、预期输出和排错提示；P0 不承诺服务器验证，P1 再评估在线执行 |
| LLM 延迟/费用不可控 | 体验和毛利受损 | 按需生成与缓存、模型分级、token 上限、用户配额、模板降级 |
| 用户自定义 Base URL 访问内网或云元数据 | SSRF、凭据和网络边界风险 | 仅接受公网 HTTPS 域名/443，禁止 IP 字面量；Worker 每次复核全部 DNS 结果并固定 IP 连接，拒绝重定向，记录最小审计；生产必须经受控 egress proxy 和云网络规则出网。 |
| 个性化信息不足或用户放弃前测 | 流程中断 | 用户在 10～20 题范围内自行选择题量、显示预计耗时；没有成功前测时不生成路线，允许在题集生成失败或取消后重新发起 |
| 动态插卡造成路线混乱 | 用户不知所措 | P0 不插卡、不用分数限制节点访问；P1 引入前先展示触发原因、保留版本并允许跳过 |
| 用户代码/提示词含敏感信息 | 隐私泄漏 | 明示不要粘贴密钥、服务端脱敏、短期保留、删除入口和访问审计 |

## 15. 待评审决策（建议默认值）
