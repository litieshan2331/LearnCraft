# LearnCraft 程序员学习 Agent — MVP 产品需求文档（候选稿）

> 版本：v0.2（MVP）
> 日期：2026-08-01
> 状态：待评审  
> 文档目的：把“目标/现状 → 前测 → 个性化路线 → 学习卡片 → 运行代码 → 测验反馈 → 基础调节”做成一条可验证的学习闭环。
>
> 配套文档：[技术栈选型](./01-技术栈选型.md) · [DDD 项目目录](./02-DDD项目目录.md)

## 1. 产品概述

### 1.1 一句话定位

面向程序员的网页学习 Agent：用户只需描述想学什么、会什么和偏好，系统通过一次规划生成可执行的学习路线，并在每张卡片中提供解释、可靠资料、代码练习和测验反馈。

### 1.2 背景与机会

程序员学习通常要反复在课程、文档、视频和代码之间切换；连续向大模型提问也很难沉淀为可执行计划。LearnCraft 将这些问答编排为有状态的工作流，把“获取信息”变成“按目标实践并验证掌握”。

### 1.3 MVP 假设

1. 用户愿意先填写少量结构化信息并完成 10～20 题单选前测；系统提供“正常”和“困难”难度卡片，并在前测题序中逐步提高难度。
2. 对一个明确的技术主题，结构化路线比泛泛的聊天答案更容易开始学习。
3. “看一个短内容 → 运行一个小练习 → 做题并得到反馈”足以形成首次价值。
4. 基于分数和代码测试的简单规则，已经能提供有感知的个性化，而不必在 MVP 中训练推荐模型。

### 1.4 推荐试点边界

为确保首版能上线验证，试点只支持 **Python 3.11 基础编程**（或评审时指定的一个单一主题），桌面网页优先，简体中文界面。架构保留扩展主题和语言的字段，但不以“支持任意主题/任意语言”作为首版验收条件。

## 2. 目标、非目标与成功定义

### 2.1 MVP 目标

- 新用户在 5 分钟内完成目标输入和前测，并得到一条可开始执行的路线。
- 用户能打开至少一张学习卡，阅读内容、运行示例/练习代码、完成测验。
- 系统能根据测验和代码结果给出下一步动作，并在必要时插入一张补强卡。
- 关键状态和尝试记录可持久化，刷新或重新登录后可以继续。
- 通过小规模试点验证“主动规划 + 动手实践”是否比单次问答更有用。

### 2.2 明确非目标（MVP 不做）

- 社区、关注/评论、社群、排行榜和分享。
- 学习进度条、成就/徽章、游戏化、完整学习报告或证书。
- 原生移动端、直播课、付费/订阅和企业管理后台。
- 同时支持多种编程语言、跨主题大而全的课程市场。
- 自动抓取任意网页、视频转写、用户上传资料的全量 RAG（首版只使用受控资料目录和链接）。
- 代码部署、持久化文件、外网访问、GPU 或长时任务；在线运行仅用于受限练习。模型推理由服务端调用托管模型 API，不属于用户代码执行环境。
- 允许用户直接修改系统提示词；只提供安全的结构化学习偏好选项。
- 由 Agent 代替教师做高风险/职业资格判断；内容需注明“辅助学习”定位。

### 2.3 MVP 成功门槛（首轮试点）

- ≥80% 试点用户能在一次会话内生成路线。
- ≥60% 生成路线的用户能打开首张卡并完成一次代码运行或测验。
- ≥40% 生成路线的用户完成首张卡的“内容 + 实践 + 测验”闭环。
- 路线/卡片生成结构化成功率 ≥95%；失效请求有可理解的重试/降级提示。
- 代码沙箱安全事件为 0，用户数据越权读取为 0。

## 3. 用户与使用场景

### 3.1 目标用户画像

**主用户：程序员学习者**

- 初级到中级，正在学习一个具体技术并希望做出可运行结果。
- 能阅读基础技术英文，但希望用中文理解重点。
- 时间碎片化（每次 15～60 分钟），不想反复搜索和整理资料。
- 需要根据已有基础、目标岗位/项目和内容偏好定制学习顺序。

**暂不服务：**需要系统课程运营、班级管理、教师批改或认证考试的机构用户。

### 3.2 核心 JTBD

> 当我想在有限时间内学会某个编程主题时，我希望只描述自己的目标和基础，就能得到一条适合我的学习路线；每一步都有可读材料、可运行练习和验证题，系统还能根据结果调整下一步，让我知道现在该做什么。

### 3.3 典型场景

1. **从零上手：**“我会一点 Python，想在两周内写一个天气 API”，系统先测基础，再安排概念、语法、实战、调试四阶段。
2. **查漏补缺：**“我能写 CRUD，但不会异步”，前测发现协程薄弱，路线优先安排异步概念和小练习。
3. **资料提炼：**用户选择“文档优先”，卡片先给短解释和官方文档链接，而不是堆砌大量搜索结果。

## 4. 产品原则与体验约束

- **先行动后扩展：**首屏引导用户明确目标并尽快生成第一张可执行卡。
- **一次输入、分步执行：**用户用一次结构化目标输入启动工作流；Agent 在后台连续完成前测、规划和内容准备，产品不把 MVP 做成无限聊天窗口。
- **每张卡一个结果：**卡片必须有可观察的掌握标准，避免长篇百科。
- **可解释的个性化：**显示“为什么安排这一卡”（来自前测薄弱点/目标），不展示不可理解的模型分数。
- **结构化 Agent：**模型输出必须通过 schema 校验、引用校验和规则校验；失败时降级为模板或重试。
- **安全运行：**用户代码与 Agent 生成代码均在隔离沙箱执行，默认无网络、限时限资源。
- **不制造虚假确定性：**外部资料显示来源和抓取时间；无法验证的链接不作为“官方资料”呈现。
- **轻量状态而非完整进度产品：**MVP 只保存当前卡、运行和测验状态以支持恢复与规则判断，不展示全局进度条、成就或学习报告。

## 5. MVP 核心流程

```text
注册/登录
   ↓
填写目标、现状、可用时间、内容偏好
   ↓
前测（用户选择 10～20 题的单选题；正常/困难；题序逐步提高难度）→ 得分、知识薄弱点
   ↓
确认并生成路线（概念 → 语法 → 实战 → 调试）
   ↓
打开学习卡 → 生成/读取内容（解释 + 资料链接；实战/调试卡含已验证 AI Demo、调用顺序、注释结果）
   ↓
在学习卡内调用独立 CodeRun 接口运行 Demo/用户代码 → 查看 stdout/stderr/测试结果、调用顺序与逐步注释结果
   ↓
完成整条路线后发起后测（用户选择 5～10 题，推荐 5～8 题；仅单选题）→ 规则评分、解释与薄弱点标签
   ↓
规则调节：解锁下一卡 / 插入一张补强卡 / 建议重试
   ↓
保存状态，进入下一张卡
```

### 5.1 状态机（最小实现）

- 路线：`draft` → `active` → `completed`（MVP 可只实现 `active`）。
- 卡片：`locked`、`available`、`in_progress`、`completed`、`needs_review`。
- 测验尝试：`in_progress`、`submitted`、`grading`、`graded`、`grading_failed`。
- 代码运行：`queued`、`running`、`succeeded`、`failed`、`timeout`。
- 同一用户同一路线只允许一个当前活动版本；重新规划生成新版本并保留旧记录。

## 6. 功能需求

优先级：**P0** = 发布阻断项，**P1** = 首轮试点应有，**P2** = MVP 后评估。

### 6.1 账户与学习者档案

| ID | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-01 | P0 | 用户注册/登录/退出；只能访问自己的学习数据 | 未登录不能读取路线、尝试和代码记录；越权请求返回 403/404 |
| FR-02 | P0 | 创建或编辑学习者档案 | 必填：目标主题、当前水平、学习目标；可选：每周时间、截止日期、操作系统、内容偏好 |

| FR-03A | P0 | 用户模型连接与选择 | 用户可保存 OpenAI-compatible `base_url`、API Key、模型名；API Key 仅可写入/覆盖并加密保存；可设置账户默认连接，创建目标、出题和 AI Demo 生成时可覆盖选择 |

| ID | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-05 | P0 | 目标输入表单 | 支持一句话自由描述 + 主题/期望成果/时间等结构化字段；缺少目标时阻止提交并给出示例 |
| FR-06 | P0 | 生成并完成前测 | 用户可选择 10～20 题，默认推荐 12 题；仅生成单选题；提供“正常”“困难”难度卡片，前测按题序逐步提高难度；显示题目进度（非全局学习进度条） |

| FR-08 | P1 | 前测异常处理 | 模型生成失败时使用受控题库；重复提交不重复扣分；允许一次重新作答并保留历史 |

### 6.6 路线后测、反馈与基础动态调整

|---|---|---|---|
| FR-22 | P0 | 路线后测出题 | 整条路线完成后，用户可选择 5～10 题（推荐 5～8 题）；仅生成单选题，题目覆盖路线关键目标；题库/模板不可用时可降级 |

| FR-29 | P0 | 用户可理解的失败态 | LLM、资料、沙箱任一服务失败时，页面显示状态、重试按钮和替代路径；不能静默卡死 |

## 7. 用户故事与验收场景

### US-01：创建学习目标

**作为**程序员学习者，**我希望**描述目标、当前水平和时间，**以便**系统生成适合我的学习计划。

- Given 用户已登录且目标字段为空，When 点击生成，Then 页面阻止提交并显示填写示例。
- Given 必填字段完整，When 提交，Then 创建一个唯一目标并进入前测，不重复创建相同请求。

### US-02：完成前测

**作为**学习者，**我希望**先回答少量问题，**以便**路线能避开我已掌握的内容。

- Given 前测可用，When 用户提交全部单选题，Then 服务端同步完成确定性评分并显示分数、能力标签和每题解析。
- Given 题库/模型暂不可用，When 用户请求或提交前测，Then 系统使用受控题库或保留答案并明确提示稍后重试；不能生成路线或静默给分。

### US-03：获得并理解路线

**作为**学习者，**我希望**看到每张卡的目标和安排理由，**以便**知道下一步做什么。

- Given 前测已完成，When 路线生成成功，Then 展示 6～12 张卡、四个阶段、前置关系和第一张可学卡。
- Given 生成结果非法，When 自动修复/重试仍失败，Then 不保存半成品，显示重试或模板路线入口。

### US-04：学习并获取资料

**作为**学习者，**我希望**按我的偏好获取短解释、文档/视频和练习，**以便**减少资料筛选时间。

- Given 用户选择“文档优先”，When 打开卡片，Then 首屏先显示解释和文档链接，且每个链接有来源/校验状态。
- Given 内容生成中，Then 用户看到可取消的加载态；刷新后可恢复或重试。

### US-05：运行代码

**作为**学习者，**我希望**在浏览器运行练习并看到错误，**以便**边做边学而不是复制粘贴到本地。

- Given 合法 Python 代码，When 点击运行，Then 返回 stdout/测试结果；在配额内重复运行不会创建重复任务。
- Given 代码超时或尝试联网，Then 任务被终止，返回安全且可理解的错误说明，宿主环境不受影响。
- Given 用户打开实战/调试卡，Then 先看到已在沙箱预运行成功的 AI Demo、调用顺序和逐步注释结果；若预运行失败，不能标记为可运行内容。

### US-06：测验和反馈

**作为**学习者，**我希望**完成卡后立即知道哪里错，**以便**决定重试还是继续。

- Given 用户在路线完成后提交 5～10 题单选后测，When 评分完成，Then 返回总分、逐题解析和薄弱标签，且记录题目与答案版本。
- Given 分数不足，Then 保留原答案并提供重试/复习提示入口，不将本路线标记为掌握。

### US-07：路线动态调整

**作为**学习者，**我希望**系统根据结果调整下一步，**以便**学习节奏与实际水平匹配。

- Given 路线后测分数 ≥80% 且相关代码任务通过，Then 当前路线标记为掌握。
- Given 路线后测为 100% 且相关代码任务通过，Then 为下一次学习提供“提高难度”建议，并说明其不会改写当前路线历史。
- Given 分数 <50% 或连续两次代码失败，Then 系统插入不超过一张补强卡，说明触发原因。
- Given 用户选择跳过补强卡，Then 记录跳过事件并允许继续，不删除历史结果。

### US-08：恢复学习

**作为**学习者，**我希望**稍后回来还能继续，**以便**不必重复前测和运行。

- Given 用户关闭页面后重新登录，Then 恢复最近活动路线、当前卡和历史尝试。

## 8. Agent 工作流与边界

### 8.1 推荐工作流节点

1. **InputNormalizer：**校验目标、档案和偏好，拒绝空泛或超出试点主题的请求。
2. **AssessmentSelector/Generator：**从受控题库选择或生成单选题：前测 10～20 题、路线后测 5～10 题；输出固定 schema、隐藏参考答案和难度元数据。
3. **AssessmentEvaluator：**仅按隐藏答案进行确定性评分，输出结构化分数、反馈和薄弱点标签。
4. **PlanPlanner：**生成四阶段路线和卡片依赖。
5. **PlanValidator：**校验数量、阶段覆盖、前置无环、时长和主题边界。
6. **CardContentGenerator：**按卡片和偏好生成解释、练习、引用；实战/调试节点还生成 Demo、调用顺序和注释结果。
7. **DemoValidator：**将 AI Demo 送入受限 Runner 预运行，比对预期输出；失败时回到修复/模板路径，不能发布为可运行 Demo。
8. **PostTestGenerator/Evaluator：**在整条路线完成后生成 5～10 道单选后测；服务端确定性评分。
9. **AdaptationPolicy：**使用显式规则决定后续学习的复习或提高难度建议；模型只能提供候选理由/标签，不能绕过规则。

### 8.2 输出契约（产品层要求）

- 所有 Agent 输出为版本化 JSON schema，再转换为 UI 文案。
- 必须携带 `trace_id`、`prompt_version`、`model`、`source_refs`（如有）和 `generated_at`。
- 缺失必填字段、循环依赖、未知主题、不可验证 URL 时不得直接展示为成功；进入修复、降级或人工可观测错误态。
- Agent 不得执行任意工具调用、访问用户私密数据或向沙箱传入未审计的网络权限。
- `AssessmentItem` 在 P0 只能是 `single_choice`，必须包含至少两个选项和隐藏答案；用户答案是不可信输入，不能触发工具调用。
- `RunnableDemoSpec` 必须包含源码、入口/输入、预期输出、调用顺序、注释结果和 Runner 验证摘要；验证失败的 Demo 不得进入成功卡片内容。

## 9. 数据需求（概念模型）

| 实体 | MVP 最小字段 | 关系/用途 |
|---|---|---|
| User | id、登录标识、创建时间 | 数据所有权和鉴权 |
| LearnerProfile | user_id、水平、语言、偏好、每周时长 | Agent 个性化输入 |
| LearningGoal | id、user_id、主题、自由描述、期望成果、截止日期 | 一次学习任务 |
| Assessment | id、goal_id、plan_id、题目版本、题型快照、题量、难度、状态、总分 | 前测/路线后测容器 |
| QuestionAttempt | assessment_id、题目、答案、得分、解析、能力标签、答案版本 | 可追溯评估 |
| LearningPlan | id、goal_id、版本、状态、生成元数据 | 路线版本化 |
| LearningCard | plan_id、阶段、序号、目标、前置、时长、状态、插入原因 | 学习单元 |
| CardContent | card_id、内容 schema、来源、偏好、版本、缓存时间、Demo/调用顺序/注释/验证摘要 | 按需内容 |
| CodeRun | card_id、代码快照、状态、输出、测试摘要、资源消耗 | 用户练习与系统 Demo 预运行反馈；敏感输出需脱敏 |
| AdaptationEvent | card_id、触发信号、策略、结果、时间 | 动态调整审计 |

数据保留：默认保留账户和学习记录 90 天（可配置）；用户可删除账户及关联数据。日志中的提示词、代码和输出应脱敏或按最小必要原则保留。

## 10. 非功能需求与质量门槛

### 10.1 性能与可用性

- 普通页面/API p95 ≤1 秒（不含 Agent/沙箱）；单选题评分同步完成，提交结果立即返回。
- 路线生成 p95 ≤60 秒，卡片内容 p95 ≤30 秒，代码运行 p95 ≤10 秒；长任务显示阶段性状态。
- Agent/资料/沙箱暂时不可用时，用户能在 3 次以内重试或走模板降级；不出现无限 loading。
- 试点期间关键链路可用性目标 ≥99%（按可观测请求计算）。

### 10.2 安全与隐私

- 代码运行采用隔离容器/微 VM，非 root、无默认网络、资源配额和超时；执行环境不共享宿主密钥。
- 所有对象按 `user_id` 鉴权；服务端再次校验，不信任前端卡片 ID。
- Markdown、URL、代码输出均进行内容过滤和 XSS 防护；错误信息不泄露路径、环境变量或内部提示词。
- API、Agent 和运行器设置速率限制、审计日志和成本上限；密钥仅从服务端密钥管理读取。
- 明确告知外部链接、模型生成内容和代码执行的风险；提供删除数据入口。

### 10.3 可访问性与兼容性

- 桌面优先的响应式网页，支持主流 Chromium/Firefox 最近两个大版本。
- 键盘可操作、颜色不作为唯一状态提示、代码/错误信息可复制。
- MVP 界面为简体中文；技术关键字保留英文并可复制。

## 11. 埋点与指标

### 11.1 核心漏斗事件

`signup_completed` → `goal_submitted` → `assessment_started` → `assessment_submitted` → `plan_generated` → `card_opened` → `content_ready` → `code_run` → `quiz_submitted` → `card_completed` → `adaptation_applied`。

每个事件至少带：匿名 user_id、goal_id、plan_version、card_id（如有）、时间、结果/错误码、trace_id。不要把密码、API key 或未脱敏代码放入分析系统。

### 11.2 指标定义

- **首次价值时间（TTFV）：**从 `goal_submitted` 到首次 `card_opened` 且内容可读，目标中位数 ≤5 分钟。
- **规划成功率：**`plan_generated / goal_submitted`，目标 ≥95%（含模板降级）。
- **首卡启动率：**`card_opened / plan_generated`，目标 ≥75%。
- **首卡闭环率：**同时完成一次合格代码运行和后测的用户 / 生成路线用户，目标 ≥40%。
- **测验有效率：**可评估提交 / 测验提交，目标 ≥98%。
- **动态调节接受率：**接受或完成补强卡的调节事件 / 调节事件总数；只做观测，不设硬门槛。
- **成本/延迟：**每条路线、每张卡的 token、费用估算、p50/p95 延迟和失败率。
- **质量与安全：**失效资料链接率、用户纠错率、沙箱违规数、越权数、敏感信息告警数。

## 12. 版本范围与里程碑

### M0：基础骨架

账号、数据库 schema、对象鉴权、Agent trace、错误码和受控题库/资料目录。

### M1：前测到路线

目标表单、10～20 题单选前测、正常/困难难度、确定性评分、路线生成/校验/展示、版本化和模板降级。

### M2：卡片学习

卡片内容生成与缓存、文档/视频引用、实战/调试 Demo schema、调用顺序/注释结果、Markdown 安全渲染。

### M3：实践闭环

Python 沙箱、AI Demo 预运行验证、学习卡内独立 CodeRun 接口、运行结果、路线完成后的 5～10 题单选后测和路线完成规则。

### M4：基础调节与试点

插入补强卡、可解释事件、限流/成本控制、端到端监控；邀请 5～10 名目标用户试用并复盘指标。

## 13. 发布验收清单（Definition of Done）

- [ ] 新用户可完成“目标 → 前测 → 路线 → 首卡”主流程，且页面有加载、空态、错误、重试态。
- [ ] 路线至少 6 张卡并覆盖四阶段；前置关系无环；Agent 输出 schema 校验通过。
- [ ] 首张实战/调试卡含解释、至少一个可验证来源、经预运行验证的 AI Demo、调用顺序、注释结果，以及在学习卡内调用的独立 CodeRun 入口。
- [ ] 合法 AI Demo/用户代码可运行；超时、异常、网络尝试均被安全终止并可理解地反馈。
- [ ] 前测为用户选择的 10～20 题单选，路线后测为用户选择的 5～10 题单选；答案不外泄，确定性评分和复习/提高难度建议均有审计记录。
- [ ] 刷新/重新登录可恢复；对象越权、XSS、沙箱逃逸和密钥泄漏测试通过。
- [ ] 关键事件、Agent trace、延迟/成本和失败率可查询；达到成功门槛后才扩大主题范围。

## 14. 风险与缓解

| 风险 | 影响 | 缓解/监控 |
|---|---|---|
| Agent 生成路线空泛、重复或超出水平 | 学习价值低 | 单主题试点、固定 schema、四阶段规则、前置无环校验、用户纠错埋点 |
| 资料链接失效或模型幻觉引用 | 误导用户 | 受控来源目录、URL 健康检查、显示来源/校验时间、失效自动降级 |
| 测验题目质量或答案泄露 | 错误学习建议或作弊 | 受控题库、隐藏答案、确定性评分、公开响应脱敏、题目版本留存并允许重试 |
| 任意代码执行导致安全事件 | 严重安全/成本风险 | 隔离运行器、无网络、配额、超时、审计和定期逃逸测试 |
| LLM 延迟/费用不可控 | 体验和毛利受损 | 按需生成与缓存、模型分级、token 上限、用户配额、模板降级 |
| 用户自定义 Base URL 访问内网或云元数据 | SSRF、凭据和网络边界风险 | P0 明示为高级开发者能力并记录连接；P1 必须加入受控 egress、私网/DNS/重定向阻断和审计，未完成前不得扩大为默认开放能力 |
| 个性化信息不足或用户放弃前测 | 流程中断 | 用户在 10～20 题范围内自行选择题量、显示预计耗时、允许以后补测但先用保守路线 |
| 动态插卡造成路线混乱 | 用户不知所措 | 每卡最多一张补强卡、显示触发原因、保留版本、允许跳过 |
| 用户代码/提示词含敏感信息 | 隐私泄漏 | 明示不要粘贴密钥、服务端脱敏、短期保留、删除入口和访问审计 |
