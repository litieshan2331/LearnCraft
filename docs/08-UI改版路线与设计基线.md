# LearnCraft 前端 UI 改版路线与设计基线

> 文档状态：已确认，作为后续 UI 设计与实现的长期基线。
> 最后确认：2026-08-30。
> 决策来源：用户已确认可全局替换现有颜色基调，并要求从第一性原理重建视觉系统。

## 1. 文档用途与优先级

本文件记录已确认的 UI 设计决策、实施顺序和边界。后续任何学习者端的视觉设计、样式改造或页面动效，都应先遵循本文件；如用户给出新的明确决策，以最新用户决策为准。

优先级从高到低如下：

1. 最新用户明确指令。
2. 项目根目录 `AGENTS.md` 的开发约定。
3. 本文件的 UI 设计基线。

## 2. 已确认的核心决策

- **全局主题替换已获授权**：不再受现有暖纸色、墨绿和直角卡片风格限制；P0 可以直接替换 `globals.css` 中的颜色、圆角和相关视觉令牌。
- **采用第一性原理设计**：界面优先服务学习者的注意力、理解与持续性，不为沿用现有样式而妥协。
- **保持业务逻辑不变**：不改接口、数据库、路由、认证、表单字段、校验规则、状态机、数据请求或按钮业务行为。
- **默认直接呈现动效**：不新增用户可见的“开启动态效果”按钮；动效为界面默认表现。
- **动效必须克制**：动效用于解释进入、切换、状态和完成反馈；禁止自动跳页、强制弹窗、闪烁或无限循环的注意力争夺。
- **不伪造学习数据**：没有接口提供的进度、时长或状态不得以真实数据口吻显示；视觉层级只能复用现有数据。

## 3. 第一性原理

### 3.1 学习者的稀缺资源是注意力

一个页面只能有一个最强主行动。信息优先级应始终回答三个问题：我在哪里、我完成了什么、下一步做什么。

### 3.2 安全感先于激励

色彩、留白和文案应降低“做错”“落后”的压力。鼓励来自清楚的进展和自然的完成反馈，不依赖高频奖励、倒计时或竞争比较。

### 3.3 动效是状态语言，不是装饰

内容出现、界面切换、选择确认和完成标记可以运动；长期循环、滚动视差和大幅缩放不能替代内容层级。

### 3.4 视觉连续性降低理解成本

相同层级的页面、卡片、按钮、状态标签和路径节点必须使用同一套视觉语言。全局主题替换后，不保留旧主题的局部色彩或直角组件作为孤岛。

## 4. 全局视觉主题

主题名称：**雾青学习空间**。

基调为低饱和雾青、清透白和少量暖金。雾青提供专注与稳定，白色提供阅读空间，暖金只用于进展与正向反馈。它比现有暖纸色更具数字产品的轻盈和探索感，同时避免深色赛博风带来的压迫。

### 4.1 浅色模式令牌

| 令牌 | 建议值 | 用途 |
| --- | --- | --- |
| `--background` | `#F3F8F7` | 页面底色，营造雾感留白 |
| `--foreground` | `#17353A` | 标题和正文主文字 |
| `--card` | `#FFFFFF` | 内容卡片和浮层表面 |
| `--primary` | `#247A80` | 唯一主行动、当前学习状态与焦点 |
| `--primary-foreground` | `#FFFFFF` | 主色上的文字和图标 |
| `--secondary` | `#E3F0EE` | 低优先级容器与分区背景 |
| `--muted` | `#EDF4F3` | 次级背景与静态占位 |
| `--muted-foreground` | `#587277` | 辅助说明文字 |
| `--accent` | `#E9F4F1` | 悬停、已选择和弱强调状态 |
| `--border` | `#D4E3E0` | 分割线与控件边框 |
| `--ring` | `#247A80` | 键盘焦点 |
| `--destructive` | `#B94C4B` | 破坏性操作与错误状态 |
| 暖金强调色 | `#E2A552` | 完成、里程碑和有限的进度强调 |

| 令牌 | 建议值 | 用途 |
| --- | --- | --- |
| `--background` | `#17282B` | 深色页面底色 |
| `--foreground` | `#EEF7F6` | 深色正文 |
| `--card` | `#20373A` | 深色卡片表面 |
| `--primary` | `#8CCFC8` | 深色模式主行动与焦点 |
| `--secondary` | `#2B474A` | 次级表面 |
| `--muted` | `#284245` | 弱化区域 |
| `--muted-foreground` | `#B7CFCD` | 次级文字 |
| `--accent` | `#315356` | 悬停与选中状态 |
| `--border` | `#406064` | 分割线与控件边框 |
| `--destructive` | `#EE9994` | 错误与破坏性状态 |

### 4.3 形状、排版和层级

- 全局基础圆角改为 `1rem`；学习主卡和重点浮层可使用 `1.25rem`。
- 保留现有中文无衬线正文与衬线标题的组合，但标题不再以过大的字距制造冷硬感。
- 正文不小于 16px，正文行高不小于 1.6；辅助文字必须保留可读对比度。
- 阴影仅使用低透明度、短扩散的柔和阴影；不使用厚重黑色投影。
- 图标沿用现有 Lucide 图标，保持线性、圆角和统一尺寸。

## 5. 动效基线

项目已包含 Tailwind、`tw-animate-css` 和 Lucide 图标，因此视觉实现优先复用现有能力，不引入新的动画依赖。

| 场景 | 规则 |
| --- | --- |
| 首屏进入 | 背景、标题、主行动和辅助区块依次淡入上移；总时长 500–700ms，区块间隔 80–120ms。 |
| 路由内容出现 | 新内容在 220–280ms 内淡入；不延迟点击响应，不以动画等待数据。 |
| 表单步骤出现 | 仅为已存在步骤添加进入动效；不改步骤状态、保存时机或表单提交逻辑。 |
| 卡片交互 | 悬停上浮 2–4px，并提升边框或阴影；时长 120–180ms。 |
| 完成反馈 | 使用一次性的勾选、进度填充或暖金高亮；时长 450–600ms，不循环。 |
| 加载状态 | 保持已有加载逻辑，仅优化为骨架层或柔和淡入；禁止大面积旋转和空白等待。 |

## 6. P0–P6 实施路线

### P0：全局视觉基础

**目标**：用“雾青学习空间”替换现有全局暖纸色主题，建立统一的卡片、圆角、边界、阴影和动效语言。

**涉及文件**：`apps/web/src/app/globals.css`，以及仅在必要时受其令牌影响的共享 UI 基础样式。

**交付内容**：

- 替换浅色与深色模式的全局颜色变量。
- 将全局圆角由当前的直角风格升级为柔和圆角。
- 定义可复用的页面进入、卡片进入、悬停和完成反馈样式。
- 保证焦点环、错误色、输入框和文本对比度在新主题下仍清晰。

**禁止事项**：不修改共享按钮、输入框等组件的接口、事件或业务行为；不引入新的依赖。

### P1：公共首页重设计

**目标**：让未登录用户先理解产品，再通过一个明确主行动开始学习，而不是面对静态介绍页。

**涉及文件**：`apps/web/src/app/(public)/page.tsx`。

**交付内容**：

- 保留现有产品介绍、登录和注册路径。
- 首屏重组为“产品定位 + 主行动 + 学习路线预览”的双栏或分层构图。
- 复用既有“概念、语法、实战、调试”阶段，绘制为可探索的学习路径预览。
- 为标题、主卡和路径节点添加错峰入场动效。
- 主行动维持现有注册链接；只调整视觉文案和样式，不更改跳转。

**验收条件**：用户在三秒内理解产品为程序员学习路线工具，并看见唯一明确的开始学习行动。

### P2：登录后学习区外壳

**目标**：将登录后的最小导航骨架升级为稳定、放松的学习工作台外壳。

**涉及文件**：`apps/web/src/app/(learn)/layout.tsx`。

**交付内容**：

- 将顶部导航改为带有背景层、学习区分组和更清晰层级的工作台导航。
- 统一导航、页面容器和内容卡的最大宽度、间距与响应式规则。
- 为内容区域提供不干扰阅读的背景氛围与淡入容器。

**禁止事项**：不新增路由状态读取、不改变 `SessionGate`、不调整现有链接和退出操作。

### P3：学习起点与目标创建

**目标**：将现有两步表单从“系统配置表单”转化为“建立学习路线的温和引导”。

**涉及文件**：`apps/web/src/modules/profile/presentation/components/onboarding-flow.tsx`。

**交付内容**：

- 以可见进度、分步标题和层级卡片呈现既有“学习画像—学习目标”步骤。
- 将单选选项和字段区块改为柔和可选择卡片，强化选中状态与键盘焦点。
- 对现有加载、保存中、完成和错误状态使用新主题和短动效。

**禁止事项**：不调整字段、默认值、Zod 校验、请求、幂等键、步骤状态或跳转逻辑。

### P4：学习目标列表

**目标**：让学习者一眼找到每个目标的当前状态和唯一下一步。

**涉及文件**：`apps/web/src/modules/profile/presentation/components/learning-goal-list.tsx`。

**交付内容**：

- 按“主题—目标名称—当前前测或路线状态—主行动—辅助信息”的顺序重构目标卡视觉。
- 用颜色、图标和布局呈现现有的前测状态、更新时间和主行动。
- 优化空状态、加载状态、错误状态与删除操作的视觉层级。

**禁止事项**：不改目标排序、删除确认、刷新、`getPrimaryAction` 判断和任何 API 调用；不凭空展示百分比学习进度。

### P5：学习路线与章节

**目标**：将章节目录呈现为可理解、可继续的学习路径，而不是一组同权重信息卡。

**涉及文件**：`apps/web/src/modules/planning/presentation/components/learning-plan-view.tsx`，以及必要时对应的章节展示组件。

**交付内容**：

- 为路线头部增加计划摘要和状态的视觉层级。
- 用纵向路径、节点编号和状态色呈现现有章节的进行中、可学习、已完成等状态。
- 强化当前章节和“进入章节”行动，弱化前置条件与辅助说明。
- 在不删除信息的前提下，改善章节卡的扫描效率和移动端排列。

**禁止事项**：不改变章节状态语义、前置关系、跳转地址、计划数据或可任选章节开始学习的规则。

### P6：视觉验收与回归检查

**目标**：确认新主题和动效符合已评审的学习者体验标准，且没有影响功能。

**检查项**：

- 首屏同时具有网页介绍和唯一明确的主学习行动。
- 用户能在三秒内看清当前位置、已有进展和下一步。
- 动效只出现在进入、切换、反馈；不存在自动跳页、自动弹窗、闪烁或循环干扰。
- 浅色、深色、桌面和移动端均具备可读的色彩对比与键盘焦点。
- 加载、空状态、错误、保存中和完成状态保持可理解。
- 对照现有链接、表单提交、数据请求和状态判断做回归检查，确保业务行为未变。

## 7. 实施顺序与交付节奏

按以下批次推进，以确保每一步可独立审查和回退：

1. **第一批：P0 + P1**。先建立主题，再让公共首页承担第一印象与探索感。
2. **第二批：P2 + P3**。将视觉语言带入登录后的工作台与学习起点。
3. **第三批：P4 + P5**。完成学习目标和学习路线的核心学习闭环界面。
4. **第四批：P6**。统一响应式、状态页、动效与业务回归检查。

每批完成后均先进行视觉审查；未通过当前批次审查，不扩展到下一批。

## 8. 后续设计时的执行规则

- 每次开始 UI 修改前，先阅读本文件与对应页面、组件、样式的现有实现。
- 所有新页面和组件必须使用“雾青学习空间”令牌、圆角和动效基线。
- 如果页面缺少支撑某个视觉设计的数据，只能设计真实的空状态或占位状态，不能杜撰业务数据。
- 如果某项视觉需求会迫使新增接口、数据库字段、状态机或模型调用，必须先停止并向用户确认。
- 任何与本文件冲突的设计建议，先在文档中记录原因并取得用户新的明确确认后再实施。
