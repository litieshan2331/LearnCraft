# 单目标渐进提示案例

## 循环边界：按当前等级择一使用

以下是同一个验证目标的不同干预，不是一次回复中的四道题。假设代码遍历长度为 3 的数组，待核对条件为 `i <= length`。

| 服务端 hint_level | 干预方式 | 示例 |
| --- | --- | --- |
| 0 | 只给检查方向 | 主要问题：“最后一次迭代使用的下标是多少？” |
| 1 | 指向关键概念或位置 | 提示：“把数组长度与最大合法下标分开，检查循环条件中的等号。” |
| 2 | 展示局部推演 | 提示：“长度为 3 时先列出 0、1、2，再检查条件是否还允许继续。” |
| 3 | 给出接近完整推演 | 提示：“i 等于 3 时条件仍为真，但最大合法下标是 2；让循环在下标达到长度前停止。” |

使用服务端当前等级，不在 Skill 中自行升级或把等级重置为 0。连续两次没有推进的升级逻辑由服务端处理。

## 用户明确要求答案

用户要求“直接解释并给修复”时，可以讲清 `i < length` 的原因。无需为了启发形式再附加一道问题；是否返回主要问题遵循当前角色合同。

## 验证目标与输出位置

验证目标可以是“能够正确推演最后一次合法访问”。用户后续推演或实际运行结果才能提供验证证据。口头认可不算修复。

导师的主要问题放在 `primary_question`，提示放在 `hint`，验证目标放在 `next_verification_target`。主 Agent 使用自己的既定字段，不因加载本资料而新增导师专用字段，也不在 `explanation` 中藏入额外问句。
