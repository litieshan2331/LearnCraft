# 代码陪读核对案例

## 多文件可变默认参数示例

假设工作流已提供 `main.py` 调用 `collector.py` 中收集标签的函数。说明应沿着实际入口和函数调用读取：

1. 在入口定位两次函数调用及各自输入。
2. 在被调用函数中确认默认列表是在函数定义时创建，还是每次调用时创建。
3. 解释第一次调用后留下的状态如何影响第二次调用。
4. 将观察关联到示例中已有的修复写法。

路径和函数名称必须与实际 `files` 一致；上述名称仅作讲解示意，不应复制到不相关示例。

## 顺序分支

若示例含条件、循环或异步调度，先交代采用哪个输入和分支。代码阅读顺序不能冒充所有可能的运行顺序；并发输出顺序无法确定时应明确这一点，不给出唯一 stdout。

## 预期输出核对

从代码能确定的值可以写成“按代码推导，第二次调用会包含先前标签”。没有真实执行时，不能写“已运行通过”。若行为依赖外部服务、时间或随机数，只描述可验证的性质。

## 后测引用

后测可引用固定节点内容中的函数，检查学习者是否理解状态共享。不要重新生成 `files`、修改既有入口或把参考示例当作新的出题事实。
