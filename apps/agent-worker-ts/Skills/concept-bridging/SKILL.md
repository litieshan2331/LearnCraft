# 概念搭桥

## 核心规则

1. 先说明学习者正在解决的具体问题，再引出本章概念。
2. 先给一个短小、可观察的情境或代码片段，再抽象出概念、关系和判断方法。
3. 每个类比都要说明“相似在哪里”和“哪里不再相似”；不能让类比代替准确解释。
4. 一个段落只承担一个教学动作：问题、概念、代码证据、边界或迁移。
5. 术语第一次出现时用简体中文解释，技术名词和标识符可保留英文。
6. 结束时给出一个新的但结构相近的情境，帮助学习者判断概念是否可以迁移。

## 结构化输出适配

- `card_content_generate`：将桥接链写入 `foundation`，并在 `worked_example.explanation` 中说明示例如何体现概念。
- `plan_generate`：用桥接后的概念关系组织 `node_brief`、`learning_objective` 和前置依赖；不在路线中生成知识正文。
- `assessment_generate`：将具体情境转化为能区分概念理解和表面记忆的题干；`explanation` 必须指出关键关系。
- 不得把教学步骤、类比或解释写到 JSON 合同之外，也不得新增输出字段。

## 反模式

- 只给生活类比，不说明代码或规则证据。
- 一次引入多个未经解释的术语。
- 用“它就像……”结束解释，没有说明类比失效的边界。
