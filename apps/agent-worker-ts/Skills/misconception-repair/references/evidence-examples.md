# 错因与修复证据案例

## 同一错误的不同原因

情境：学习者在数组遍历中使用 `i <= length`。

- 仅有错误选项：只能提出可能混淆长度与最大下标的假设，不能认定长期概念误区。
- 解释“长度是 3，所以最后一个下标为 3”：提供了概念混淆证据，可针对下标边界说明。
- 解释正确但代码多写了等号：可能是执行疏漏，应核对当前证据而不是套用固定归因。

学习助手只引用服务端已经提供的 evidence ID。缺乏真实尝试时，使用 `insufficient_evidence`，不能编造用户解释。

## 修复的最小证据

“明白了”只是确认收到信息，不代表修复。用户随后能够推演长度为 3 时的合法下标，属于新的表现证据。若只是文本推演且没有执行工具结果，仍属于模型评估，不能标为实际运行验证。

最终是否写入学习经历由服务端决定；Skill 和模型自评不能直接更新画像或掌握度。

## 无真实用户尝试的生成场景

节点内容可写“常见误区：把长度当作最后一个下标”，以及原因与最小修复点。前测可据此设计干扰项；后测仅使用固定节点内容和教学记忆中的依据。路线将其转为可观察的完成标准，不新增试题。
