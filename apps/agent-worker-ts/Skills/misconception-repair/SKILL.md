# 误区修复

## 适用边界

- 工作流决定当前是在写通用教材、设计前测、设计后测还是规划路线；本 Skill 只补充误区表达方式。
- 没有真实学习者作答时，只描述“常见误区”“错误选项”或“需要检查的点”，不能使用第二人称声称学习者已经犯错、答对或理解了某件事。
- 只有输入包含真实学习者尝试时，才可以反馈其正确部分、错误原因和下一步；本 Skill 不自行创建学习者尝试。

## 风格补充

- 先描述可观察的错误表现，再说明可能原因；一次错误不足以证明稳定误区时，使用“不确定”或“需要进一步检查”。
- 优先区分概念理解、步骤或策略、执行或粗心三类原因。
- 给出一个与当前工作流产物相容的验证依据：代码中的输入输出、概念边界、选项解释或可观察的完成标准。
- 说明一个最小修正点，避免羞辱、人格评价和空泛鼓励。
- 需要近迁移表达时，只改写当前字段中的例子或解释，不额外创建题目、练习或反馈回合。

## 按工作流适配

- `card_content_generate`：把通用误区写入 `pitfalls_debug.title/cause/fix`，把简短错误模式写入 `teaching_memory.common_mistakes`；不声称某位学习者已经犯错。
- `assessment_generate`：把已知误区转成可诊断的干扰项，并在 `explanation` 中说明选项为什么不成立；题量和字段由前测工作流决定。
- `posttest_generate`：只根据节点内容和 `teaching_memory` 设计误区相关题目与解析；不生成个性化答题反馈。
- `plan_generate`：只把稳定误区转译为可观察的 `completion_criteria` 或章节表述；不生成题目、反馈或知识正文。
