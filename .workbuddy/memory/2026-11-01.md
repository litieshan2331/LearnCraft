## 面试素材整理：plan_generate 的 Human-in-the-Loop

分析并沉淀了 HITL 的技术要点与简历 bullet 写法（对应未提交改动，分支 feature/A）。

核心机制（按代码实际实现记录）：
- LangGraph `interrupt()` / `Command({ resume })` 做图级暂停恢复，Checkpointer 用 PostgreSQL（`agent.checkpoints` 表），因此状态跨进程、跨请求、可崩溃恢复。
- 状态机扩展：agent_runs 新增 `waiting_for_human`、`expired`；新增 `agent.human_reviews` 表（waiting/submitted/expired/cancelled，agent_run_id 唯一）。
- 提交入口 `POST /api/v1/agent-runs/{id}/human-review`：单事务内对 agent_runs + human_reviews 双 `FOR UPDATE` 行锁，Idempotency-Key（唯一索引 uq_human_reviews_run_idempotency）幂等，答案覆盖性/选项归属/custom_text 边界三重校验，2 小时 expires_at 过期即置 expired。
- 恢复链路：Web 写 Outbox `agent.run.requested` 复用现有队列重新入队；Worker 侧 `pg_try_advisory_lock(hashtextextended(thread_id,0))` 串行同一 thread，超时抛 `AGENT_HITL_THREAD_LOCK_TIMEOUT` 并归类为可重试错误交给队列退避。
- 契约版本化：`schema_version=plan_generation_human_review.v1`、`graph_version=plan_generate.hitl.v1`；问题批次与答案批次双向 Zod 校验。
- 答案以 JSON 拼接到生成阶段 user prompt 尾部，恢复后从断点继续，不重跑。

简历 bullet 定稿方向（推荐版）：
「基于 LangGraph interrupt/resume + PostgreSQL Checkpointer 实现跨进程 Agent 人工确认：任务中断后释放 Worker 进程，答案经幂等事务提交并由 Outbox 重新入队，advisory lock 保证多 Worker 下精确恢复一次，避免整轮路线重跑。」

面试追问准备重点：为什么不用轮询/内存等待、checkpoint 存什么、用户不答怎么办、并发重复恢复、重复提交、为何插在生成前（省 token）。

## HITL 简历 bullet 的量化口径（用户要求：问题→方案→耗时/token 降幅）

项目内暂无实测数据，先落占位符。取数列：`agent.agent_runs.input_tokens/output_tokens/estimated_cost_usd/started_at/finished_at/graph_version`，配合 `agent.human_reviews` 判断是否命中澄清。

两个口径（面试被追问"这数怎么来的"时用）：
- 口径 A 命中澄清的任务（推荐写这个）：旧 = 2×C（生成→不满意→重生成），新 = C + c（澄清问答约 1–2k token）；C=20k、c=1.5k 时 token 降幅约 46%。
- 口径 B 全量平均：设重跑率 R=30%，旧 = 1.3C，新 = C + c，降幅约 17%。

耗时口径必须写"系统执行耗时（剔除人工等待窗口）"：HITL 会等用户答题（分钟~小时级），算端到端 wall-clock 反而变长。

发现的技术债务（待修，也影响测量真实性）：暂停前那次澄清模型调用的 token 未落库 —— `markWaitingForHuman` 只接收 review，未接收 `result.usage`，且暂停分支直接 return 不走 markSucceeded。导致按 agent_runs 的 token 列对比会低估新方案消耗、虚高收益。修法：给 markWaitingForHuman 增加 usage 参数并累加写入。

## bullet 最终定稿（允许写通用技术名词，禁写项目自定义标识符）
