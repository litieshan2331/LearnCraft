# Design

## Context

参见 `proposal.md` 的 Why。当前 Worker 已有 `StateGraph`、PostgreSQL Checkpointer、自定义 OpenAI-compatible SSE 网关、ReAct 轮数限制和串行工具节点；`@langchain/core` 与 `@langchain/langgraph` 已安装，但 Worker 尚未使用 LangChain 高层 Agent/Tool 抽象。Web 内部接口当前负责学习记忆候选验证与写入，并从 `learning_experience_memories` 查询历史记忆。现有记忆表、会话消息和 Checkpoint 属于不同职责，不应因替换记忆实现而一并删除。

## Goals / Non-Goals

**Goals:**

- 使用 LangChain Agent/Tool 承载三个 Agent 的 ReAct，使用 LangGraph 管理父流程、共享状态、Checkpoint 和恢复。
- 让子 Agent 只能由主 Agent 委派调用，子 Agent 仅可使用只读工具，并通过 State 与工具结果返回主 Agent。
- 允许自然语言自由输出，同时为程序控制字段保留独立、窄化的类型合同。
- 为未来 mem0 接入保留可替换端口设计，但本次不接入长期记忆运行时。
- 停止学习助手旧业务表的读写，但在数据保留策略确定前保留既有数据和迁移回滚能力。

**Non-Goals:**

- 不改变四类既有生成工作流的结构化输出合同或 ReAct 执行器。
- 不将长期记忆原文、Agent 内部消息或轨迹加入公开 API。
- 不在本变更中选定 Mem0 Platform、自托管、具体模型、向量存储、保留期限或存量记忆销毁策略。
- 不把 mem0 作为事实权限源；会话所有权、证据来源和用户身份仍由 LearnCraft 服务端验证。

## Decisions

1. **LangChain Agent 管理 ReAct，父 LangGraph 管理流程。** 主 Agent 使用 LangChain Agent 接收业务只读工具和两个委派工具；两个子 Agent 使用独立提示词与只读工具集。外层 LangGraph 继续负责初始化、身份检查、持久化、Checkpoint、恢复和结束条件。相比手写每轮 `model.complete` 与工具游标，这将 ReAct 的常规循环收敛到统一 Agent 抽象，同时保留项目需要的会话级恢复边界。

2. **用委派工具维持单向 Agent 关系。** `analyze_wrong_answer` 和 `generate_socratic_question` 只在主 Agent 的工具集中注册。委派执行器从父图 State 构建可信任务上下文后调用对应子 Agent；子 Agent 工具集中不注册委派工具。子 Agent 的自由文本结果写入对应 State 字段，并作为工具结果返回主 Agent。这样主 Agent 可以综合子结论，而子 Agent 不需要也不能直接调用另一个 Agent。

   子 Agent 执行失败时，委派工具抛出 `ChildAgentInvocationError` 一类的稳定异常，包含子角色、失败阶段、可重试标志和脱敏错误码，不写入成功结果或空占位状态。LangChain 主 Agent 将该工具异常作为当前 ReAct 回合的工具错误接收，由主 Agent 决定重试、调用另一个子 Agent、使用已有上下文降级回答或停止本轮；只有主 Agent 形成最终决策后，父图才进入回复持久化节点。若主 Agent 自身无法完成最终决策，异常才由父图按运行失败策略处理。

3. **共享状态与模型文本分离。** State 保存会话消息、诊断文本、导师建议、提示等级、待回答问题、验证目标、证据、活动子 Agent、预算和持久化游标等可恢复数据。自然语言内容使用字符串字段，不要求 JSON 解析。涉及工具参数、业务身份、权限、证据 ID、有限枚举或数据库写入的值继续使用 Zod/端口合同；不能从自由文本中推断权限或直接执行记忆写入。

4. **通过模型适配器复用现有安全网关。** 当前网关承担 SSE 聚合、受控出网、重试、预算、备用模型、限流和轨迹。LangChain Agent 不得直接接入 Provider 或绕开该网关。实现阶段需提供符合 LangChain ChatModel/tool-call 消息契约的适配层，或以等价方式扩展现有网关；选择前以真实工具调用、流式结果、错误分类和用量轨迹测试适配行为。相比新增 Provider 客户端，这能保留现有出网和计费边界。

5. **子 Agent 的 Checkpoint 边界保持显式。** 不把包含长时间模型和工具循环的子 Agent 包装成不可观察、不可恢复的普通函数。若 LangChain Agent 工具执行不能把内部步骤写入父 Checkpoint，则将子 Agent 保留为可恢复子图/节点，并由委派工具调用子图；所有外部写操作仍需稳定幂等键。选型以“工具完成后进程崩溃、从 Checkpoint 恢复时不重复业务写入”为验收标准。

6. **mem0 延期。** 当前 Worker 不读取或写入长期记忆，不将完整会话发送到外部记忆服务。`memory/` 中的端口和测试替身只作为未来独立变更的草案保留；生产部署、完整对话出网、传输保护、区域、保留期限和删除策略确认后再接入。

7. **旧记忆停止参与运行，存量数据不自动销毁。** 切换时移除学习助手对 `learning_experience_memories` 的上下文读取和候选验证/写入调用；先保留表、迁移历史和已有记录，避免因功能切换立即发生不可逆丢失。存量导入 mem0、设置保留期限、删除旧记录或删除表均需用户单独确认，并在实施前提供明确影响、回滚方式和数据处理范围。

8. **旧记忆链路退役。** Worker/Web 不再查询或写入 `learning_experience_memories`，不再提供旧候选验证/写入接口；数据库表、迁移和历史记录暂时保留，等待独立的数据保留或迁移决策。

## Risks / Trade-offs

- [LangChain ChatModel 适配可能与项目自定义 SSE、工具调用、备用模型和轨迹语义不一致] → 在替换 Agent 节点前建立适配契约测试，检查工具参数分片、调用 ID、用量、重试、取消和失败事件。
- [子 Agent 封装为工具后可能失去逐节点恢复能力] → 验证子图 Checkpointer 命名空间与父 State 恢复；将进程中断测试纳入验收，禁止以不可恢复的长函数掩盖状态边界。
- [自由文本无法直接驱动提示升级、待回答问题或学习记忆写入] → 将自然语言与窄化的控制状态分离，由工具或服务端节点更新 State；不尝试从自然语言解析安全敏感状态。
- [mem0 部署形态会改变出网、费用、延迟和数据驻留] → 使用独立适配器和显式配置；在部署选择和数据出网策略获确认前，不接入生产凭据或启用生产写入。
- [mem0 请求完成与 Checkpoint 保存之间可能崩溃] → 使用稳定操作键和可恢复操作状态；若目标 mem0 形态不提供幂等写入，则在选定部署前验证本地账本方案和重复调用边界。
- [旧记忆在停用后继续留存数据库] → 本次只停止运行时读写；将存量迁移/销毁单独列为待确认决策，提供数据量、保留和回滚评估后再操作。

## Migration Plan

1. 添加 LangChain Agent/Tool 与现有模型网关的兼容适配，并让三个 Agent 在离线假模型下跑通 ReAct、工具白名单和自由文本。
2. 将父图 State 和 Checkpoint 切换到新的消息/控制状态结构；提供旧 Checkpoint 版本识别与安全恢复策略。若无法无损升级旧运行，部署时先排空在途学习助手运行，再启用新图。
3. 停止旧 `learning-memory` 内部接口调用和旧表上下文查询，退役旧 Repository 方法、工具和 schema 引用。
4. 将 mem0 测试替身及适配器接入另一个变更；生产部署形态、数据来源策略及出网参数须在启用前确认。
5. 在用户确认存量策略后，单独执行选择的导入、保留或销毁流程；数据库迁移须先备份并通过 `pnpm db:check` 和迁移验证。
6. 回滚时恢复旧 Worker 图与旧内部接口装配；新 mem0 写入不会自动反向同步到旧表，因此切换后产生的新记忆不保证可由旧版本读取。回滚窗口和数据双写要求在生产发布方案中确认。

## Open Questions

- mem0 使用自托管服务还是 Mem0 Platform，以及相应的主机、区域、认证、限额和费用配置（后续变更）。
- 完整会话对话发送给所选 mem0 部署的出网批准、传输保护、区域、保留期限和删除策略。
- 当前 `learning_experience_memories` 存量记录的保留期限、是否迁移至 mem0、以及最终删除审批流程。
- mem0 删除操作由账户删除流程自动触发，还是同时提供用户主动查看/删除记忆的产品入口。
